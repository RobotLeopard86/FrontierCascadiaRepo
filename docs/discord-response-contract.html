How Claude Code speaks in the channel

Every turn lands as one structured message: what was done, the code that changed, the diff, the verification — and reasoning that stays folded away until somebody presses Show thinking. This is the block order, the widget wiring, and the gaps in src/ that still have to be built.

The block order

Order is the contract. A reader scanning the channel on a phone sees the claim first and the reasoning last — never the reverse. Blocks are omitted when empty, never reordered.

01

Headline always

One line, past tense, naming the change — not the intention. No emoji, no "Sure!", no restating the request.

Channel resolution now fails fast when GUILD_ID is unset
02

Narration always

Two or three sentences of plain professional prose: what the problem was, the approach taken, and anything the reader has to decide. This is the part a human reads when they are not reading anything else.

resolveChannelId() threw a generic "not found" when the guild lookup silently failed, so a missing GUILD_ID surfaced as a bad channel name. The guard now runs before the fetch and names the missing variable.
03

Changed code when files changed

One fenced block per file, language-tagged, line-numbered, and headed by a clickable path:line. Excerpt the changed region with two lines of context — never paste a whole file into the channel.

src/discord.ts:16 ```ts 16 │ if (!GUILD_ID) { 17 │ throw new Error('GUILD_ID is required …'); 18 │ } ```
04

Diff when files changed

git diff in a diff-tagged fence so Discord colors the gutters. Over 25 lines or 1,500 characters it becomes a changes.diff attachment with the --stat summary inline, so the message stays scannable.

```diff - const guild = await client.guilds.fetch(GUILD_ID); + if (!GUILD_ID) throw new Error('GUILD_ID is required'); + const guild = await client.guilds.fetch(GUILD_ID); ```
05

Verification always

The command that was actually run and its real result. A failure is reported verbatim in this slot — the same slot, the same prominence. Nothing is claimed here that was not run this turn.

$ pnpm build → built in 412ms, 0 errors
06

Thinking folded by default

Last, always last, and hidden unless the channel asked for it. Captured at post time and stored with the message so revealing it never costs another model call.

Thinking — 2 of 9 steps

The error message is the only signal the caller gets, and it currently conflates two failures: an unset environment variable and a genuinely missing channel. Those have different fixes, so they need different messages.

Checked whether the snowflake branch above can reach this code with an empty GUILD_ID — it cannot, the regex returns first, so the guard is safe to place before the fetch rather than inside the catch.

Where the blocks come from

The formatter sees a finished turn, not a live stream: it collects the four sources, orders them into the contract, and posts once. Thinking is captured here even when it will not be shown, because the toggle later reads from this record.

What the widget does

One button press, one message edit, no model involvement. The loop below is the whole mechanism — and the arrow that matters is the one that is absent: nothing goes back to Claude Code.

Whose thinking gets shown

A Discord message has one body for everyone who can see it, so “toggle thinking” has two incompatible readings. The difference is worth drawing, because the bot has to commit to one per press.

Recommendation: ship both, on one button

Press reveals thinking ephemerally — the cheap, private, default-safe read. Shift-equivalent (a second button, Show for channel, appearing in the ephemeral reply) promotes it into the shared message for everyone.

That keeps the blast radius of a curious press at zero, while still allowing a deliberate "everyone should see this" when the reasoning is the point of discussion. A per-channel default — /dh thinking on|off — sets where new messages start.

Hard limits the formatter respects

Discord truncates silently in some places and rejects outright in others. These are the numbers the length cap is derived from.

2,000 message content

Plain body. Reason enough to put slots 01–05 in an embed instead.

4,096 embed description

Where the narration, code and diff live. Overflow becomes an attachment.

6,000 embed total

All fields summed across one message. Thinking alone can exceed it.

5 buttons per row

Three used: toggle, copy diff, open thread. Room to grow.

3s interaction ack

Call deferUpdate() first; re-render after. Late acks show an error to the presser.

25 diff lines inline

Our rule, not Discord's. Past it, attach changes.diff and keep the --stat.
